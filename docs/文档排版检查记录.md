# 文档排版检查记录
## 1、检查范围
检查对象为docs目录下全部后缀为`.md`的Markdown文档，清单如下：
1. README_DOCS.md
2. 一、项目概述.md
3. 二、需求分析.md
4. 三、系统设计.md
5. 四、详细设计.md
6. 五、代码实现.md
7. 六、测试.md
8. iDrug前端功能说明.md
9. 运行效果截图说明.md
10. 文档排版检查记录.md

注：文件夹内docx格式文件为Word文档，仅作为备份文件，不参与Markdown语法校验。

## 2、检查项目
### 2.1 文件编码校验
全部md文件统一保存为UTF‑8编码，无ANSI、GBK编码格式，上传GitHub后不会出现中文乱码、二进制字符异常。

### 2.2 Markdown语法校验
1. 标题严格遵循 `# `、`## `、`### ` 书写规范，#后添加空格，GitHub可正常渲染标题层级；
2. 不同章节段落之间进行空行处理，实现段落分隔，预览页面排版分层清晰；
3. 纯文字内容编写，不存在无效图片链接；md文档与screenshots截图文件相互独立；
4. 不存在零宽字符、特殊不可见符号、未闭合代码块，不会造成页面渲染空白。

### 2.3 文件命名与目录校验
1. 所有md文档统一放置在docs目录下，项目目录结构规范；
2. 文件后缀为`.md`，没有隐藏.txt后缀，不存在直接将docx文件重命名为md文件的问题；
3. 文件命名格式统一，满足项目提交规范。

## 3、最终检查结论
docs目录下全部Markdown文档编码正确、标题层级规范、段落排版整齐，可在GitHub正常预览渲染，整套文档材料符合项目交付要求。
