# 六、测试

本章用于说明 iDrug 平台在课程阶段的测试工作，重点验证系统功能是否能够按照需求正常完成、异常输入是否能够被处理、模型调用和个性化推荐流程是否稳定。与第七章不同，本章关注“系统是否正确、稳定、可验证”；第七章关注“系统运行后呈现什么效果、用户如何操作”。

## 6.2 测试范围与方法

本次测试覆盖用户访问、用户登录、DTI 预测、个性化推荐、多场景模型预测、药物与蛋白查询、推荐结果保存、历史结果管理和异常输入处理等功能。

主要测试方法如下：

1. 功能测试：按照用户使用流程逐项验证页面功能是否可用。
2. 接口测试：检查后端接口是否能正确接收参数、返回 JSON 数据和错误提示。
3. 异常测试：输入空值、非法任务类型、不可查询 ID 等数据，检查系统是否给出合理提示。
4. 模型调用测试：验证不同任务类型是否能映射到对应模型或演示结果。
5. 兼容性测试：在常用浏览器中检查页面显示和基本交互。
6. 回归测试：针对已修复 bug 重新执行相关用例，确认问题不再出现。

## 6.5 Bug 修改记录

| Bug 编号 | 问题描述 | 问题原因 | 修改方式 | 当前状态 |
| --- | --- | --- | --- | --- |
| BUG-01 | 用户输入中文分号或多种分隔符时，后端解析不稳定 | 前端输入格式不统一，后端未统一替换特殊符号 | 在接口解析时将中文分号替换为英文分号，并对输入进行 strip 处理 | 已修复 |
| BUG-02 | 药物或蛋白外部接口查询失败时，页面可能无法展示结果 | 外部数据库存在网络波动或查询为空的情况 | 增加本地缓存优先、在线查询补全和 fallback 降级返回 | 已修复 |
| BUG-03 | 模型推理中间文件容易残留 | 模型脚本需要 CSV 输入输出，早期缺少统一临时目录清理 | 使用运行时临时目录保存输入输出，并在 finally 中清理 | 已修复 |
| BUG-04 | 个性化推荐在缺少临床元数据时排序说明不清晰 | 部分药物无法匹配完整临床标签 | 增加 metadata_status 字段，区分完整、部分和缺失元数据 | 已修复 |
| BUG-05 | 未登录用户也可能触发保存接口 | 保存接口早期权限校验不足 | 保存前读取 session 用户名，未登录时返回 Login required | 已修复 |
| BUG-06 | 历史结果缺少用户隔离，存在误读其他记录的风险 | 保存目录未充分按用户划分 | 按 username 创建独立目录，并在详情和删除接口中检查所有者 | 已修复 |
| BUG-07 | 非法任务类型可能进入模型调度层 | 前端选择值和后端任务映射缺少统一校验 | 在 PredictionModelsRunView 中检查 task_type 是否存在于 TASK_CONFIG | 已修复 |
| BUG-08 | 个性化排序中某些分数可能超出展示范围 | 多个加减项叠加后可能超过 0 到 1 区间 | 使用 clamp_score 对最终分数和分项分数进行约束 | 已修复 |

## 6.6 测试小结

通过本章测试可以看出，iDrug 平台的核心业务流程基本稳定，能够支撑课程演示和项目验收。系统在模型调用、查询降级、异常输入处理、用户结果保存等方面均进行了必要的健壮性处理。后续如果进入更大规模使用阶段，还需要补充自动化测试、并发测试、接口性能测试和更严格的数据安全测试。
